Seção 01

Introdução: O Servidor Conta o Que Aconteceu

A maior parte da internet roda em Linux, inclusive a loja online da Ipê Store. Quando um alerta aponta para um servidor Linux, o analista precisa responder em minutos: alguém entrou? Ganhou privilégio? Deixou um jeito de voltar? A resposta está em poucos lugares conhecidos, e a linha de comando é a forma mais rápida de chegar lá. Neste estudo você vai investigar o web-loja01 com as mesmas ferramentas que usaria num servidor real.

Onde Fica Cada Coisa (FHS)

O FHS (Filesystem Hierarchy Standard) padroniza os diretórios. Os que mais importam numa investigação:

Permissões

Cada arquivo tem dono, grupo e três trios de permissões: leitura (r = 4), escrita (w = 2) e execução (x = 1), para dono, grupo e outros. chmod 750 dá rwx ao dono, r-x ao grupo e nada aos outros. A umask define o que é retirado na criação: com 022, arquivos nascem 644 e diretórios 755.

  • SUID (4000): o programa roda com os privilégios do dono. Legítimo em passwd e sudo; numa cópia do bash pertencente ao root, é uma porta de volta para root (T1548.001).
  • SGID (2000): roda com o grupo do arquivo; em diretórios, os arquivos novos herdam o grupo.
  • sticky bit (1000): num diretório como /tmp (1777), só o dono apaga os próprios arquivos.

Contas ficam em /etc/passwd (legível por todos, sem senha) e os hashes em /etc/shadow (só root e grupo shadow). O prefixo do hash indica o algoritmo: $6$ é SHA-512 crypt; $y$ é yescrypt, o padrão das distribuições recentes. Uma conta com UID 0 além do root é sinal de invasão.

🔑 sudoers com NOPASSWD: ALL

Uma linha como deploy ALL=(ALL) NOPASSWD: ALL no sudoers transforma quem descobrir a senha do deploy em root, sem nenhuma outra pergunta. Mesmo regras restritas podem escapar: programas como vim, find ou tar permitem abrir um shell, e o projeto GTFOBins cataloga esses casos. Edite o sudoers sempre com visudo.

Quem Entrou

O SSH registra cada tentativa no auth.log; com systemd, o mesmo aparece em journalctl -u ssh (a unidade se chama sshd no RHEL). Muitas linhas Failed password de um IP, seguidas de Accepted password do mesmo IP, indicam força bruta bem-sucedida (T1110). Os pipes resumem milhares de linhas em segundos:

bash — triagem de um servidor 
# IPs com mais falhas de senha (funciona com e sem "invalid user")
grep "Failed password" /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn | head

# Logins aceitos
grep "Accepted" /var/log/auth.log

# Processos e portas abertas, com o programa dono de cada porta
ps aux
ss -tlnp
lsof -i -P -n

# Binários SUID e arquivos graváveis por todos
find / -perm -4000 -type f 2>/dev/null
find / -perm -0002 -type d 2>/dev/null

# Persistência
ls -la /etc/cron.d; cat /etc/crontab; crontab -l -u root
systemctl list-timers; systemctl list-unit-files --type=service --state=enabled
🧮 A coluna do IP muda

Em Failed password for root from 198.51.100.23 port 50100 ssh2, o IP é a 11ª coluna. Em Failed password for invalid user admin from 198.51.100.23 port 50106 ssh2, as duas palavras extras empurram o IP para a 13ª. Contar só $11 mistura IPs com nomes de usuário (admin, ubuntu), e a contagem do atacante cai pela metade. Conte a partir do fim ($(NF-3)) ou extraia o IP com grep -oE '[0-9]+(\.[0-9]+){3}'.

Processos e Portas

ps aux mostra cada processo com usuário e linha de comando; procure shells rodando de /tmp, processos com nomes de sistema em caminhos estranhos e conexões reversas. ss -tlnp lista as portas em escuta e o processo dono; uma porta alta aberta por nc é um backdoor. lsof liga arquivos e conexões aos processos que os usam.

Um cron que roda a cada minuto um curl ... | bash baixa e executa o que o atacante quiser, sempre que quiser. Remover o arquivo do cron sem trocar as credenciais e sem tirar a chave SSH extra só adia a volta dele.

Seção 05

Questões de Fixação e Entrevista

Questão 1 (Permissões): O que significa o modo 4755 num arquivo, e quando ele é preocupante?
Ver resposta explicada

Resposta: SUID ligado (4), dono com rwx (7), grupo e outros com r-x (5): o programa roda com os privilégios do dono.

É normal em passwd e sudo. Num shell ou num binário em /tmp pertencente ao root, dá root a qualquer usuário que o execute.

Questão 2 (umask): Com umask 027, com que permissões nasce um diretório novo?
Ver resposta explicada

Resposta: 750 (rwxr-x---).

Diretórios partem de 777 e arquivos de 666; a umask retira bits. 777 menos 027 dá 750; um arquivo nasceria 640.

Questão 3 (auth.log): Por que awk '{print $11}' conta errado os IPs das falhas de SSH?
Ver resposta explicada

Resposta: Porque nas linhas com "invalid user" o IP fica na 13ª coluna, e a 11ª passa a ser o nome do usuário inexistente (admin, ubuntu, test).

Conte do fim com $(NF-3) ou extraia o IP com grep -oE. Sempre confira o formato de algumas linhas antes de confiar num resumo.

Questão 4 (sudoers): A regra ana ALL=(root) /usr/bin/vim /etc/nginx/nginx.conf limita a Ana a editar um arquivo?
Ver resposta explicada

Resposta: Não. Dentro do vim ela pode abrir um shell (:!bash), que roda como root.

Para editar como root com segurança, use sudoedit, que edita uma cópia com os privilégios do usuário. O GTFOBins lista os programas que permitem esse tipo de fuga.

Questão 5 (Persistência): Você apagou o cron malicioso e trocou a senha do usuário invadido. Que outra persistência comum precisa ser verificada?
Ver resposta explicada

Resposta: As chaves em ~/.ssh/authorized_keys, além de serviços e timers do systemd e arquivos de inicialização do shell.

Uma chave SSH do atacante (T1098.004) permite entrar sem senha, então trocar a senha não basta.

Questão 6 (Portas): ss -tlnp mostra 0.0.0.0:4444 aberto pelo processo nc. O que isso indica?
Ver resposta explicada

Resposta: Provavelmente um backdoor: o netcat esperando conexões, possivelmente entregando um shell.

Confira a linha de comando com ps, isole o servidor e colete a memória antes de encerrar o processo (Estudo 19).

Seção 06

Fatos Essenciais, Referências e Próximos Passos

1. Permissões

r=4, w=2, x=1; SUID 4000, SGID 2000, sticky 1000; umask retira bits.

2. Quem entrou

auth.log ou journalctl; conte IPs do fim da linha com $(NF-3).

3. O que roda

ps aux, ss -tlnp e lsof ligam processos, portas e arquivos.

4. Persistência

cron, systemd, authorized_keys e .bashrc; sudoers sem NOPASSWD amplo.
