Introdução: A Mesma Ferramenta dos Dois Lados

O PowerShell administra o Windows inteiro e, por isso mesmo, é uma das ferramentas favoritas de quem invade (T1059.001). Para o analista, ele é o jeito mais rápido de perguntar a uma máquina o que aconteceu: quais eventos houve, o que está rodando, o que inicia sozinho. Neste estudo você vai aprender o suficiente de PowerShell para investigar a EST-FIN-07, uma estação do financeiro da Ipê Store que abriu o anexo errado.

Cmdlets e Pipeline de Objetos

  • Os comandos, chamados cmdlets, seguem o padrão Verbo-Substantivo: Get-Process, Get-Service, Get-WinEvent. Get-Command lista os disponíveis, Get-Help explica cada um e Get-Member mostra as propriedades do que um comando devolve.
  • O pipeline de objetos é a grande diferença em relação ao bash: o | passa objetos com propriedades, não texto. Em vez de recortar colunas com awk, você filtra por propriedade com Where-Object, escolhe colunas com Select-Object, ordena com Sort-Object e conta com Group-Object.
  • Get-WinEvent -FilterHashtable filtra no próprio log, antes de trazer os eventos, o que é muito mais rápido do que trazer tudo e filtrar depois com Where-Object.
PowerShell — consultas de investigação 
# Falhas de logon por IP de origem (IpAddress é o campo 19 do 4625)
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625} |
  ForEach-Object { $_.Properties[19].Value } | Group-Object | Sort-Object Count -Descending

# Todos os campos de um evento, a partir do XML
$e = Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4720} -MaxEvents 1
([xml]$e.ToXml()).Event.EventData.Data | Select-Object Name, '#text'

# Persistência: chaves Run, serviços fora dos caminhos usuais, tarefas agendadas
Get-ItemProperty 'HKLM:\Software\Microsoft\Windows\CurrentVersion\Run', 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run'
Get-CimInstance Win32_Service | Where-Object PathName -notmatch 'Windows|Program Files' |
  Select-Object Name, PathName, StartName
Get-ScheduledTask | Where-Object TaskPath -notlike '\Microsoft\*'
🧱 Execution policy não é barreira de segurança

A execution policy evita que um usuário rode um script por engano, mas qualquer pessoa a contorna com -ExecutionPolicy Bypass ou colando o código no console. As defesas reais são outras: AMSI (o antivírus inspeciona o script já decodificado, antes de ele rodar), Constrained Language Mode com controle de aplicações (WDAC ou AppLocker), log de ScriptBlock e a remoção do PowerShell v2, que não tem AMSI nem log e é usado em ataques de downgrade.

Sysmon e ScriptBlock

O Sysmon acrescenta eventos que o Windows não gera sozinho: 1 (processo criado, com processo pai e hash), 3 (conexão de rede), 11 (arquivo criado) e 13 (valor de Registro alterado). O log de ScriptBlock do PowerShell (evento 4104) registra o script que de fato rodou, já decodificado: um comando escondido em Base64 com -enc aparece em texto claro.

Persistência no Registro

As chaves ...\CurrentVersion\Run executam um programa a cada logon (T1547.001). Em HKLM valem para todos os usuários e exigem administrador para gravar; em HKCU valem só para o usuário e não exigem privilégio, por isso são as preferidas de um malware que entrou por um usuário comum. Compare cada valor com o que é conhecido na empresa e desconfie de executáveis em C:\Users\Public, AppData ou Temp.

🧾 Onde ficam os campos de um evento

No Windows real, campos como TargetUserName e IpAddress não são propriedades diretas do objeto devolvido por Get-WinEvent: ficam na lista .Properties, por posição, ou no XML do evento, que se lê com [xml]$e.ToXml(). No laboratório abaixo eles aparecem como propriedades diretas, para simplificar.

Questões de Fixação e Entrevista

Questão 1 (Pipeline): Qual é a principal diferença entre o pipeline do PowerShell e o do bash?
Ver resposta explicada

Resposta: No PowerShell passam objetos com propriedades; no bash passa texto.

Por isso se filtra com Where-Object { $_.Status -eq 'Running' } em vez de recortar colunas. Get-Member mostra as propriedades disponíveis.

Questão 2 (Execution policy): A política de execução está em Restricted. Isso impede um atacante de rodar PowerShell na máquina?
Ver resposta explicada

Resposta: Não. Ela é contornada com -ExecutionPolicy Bypass, com -enc ou colando o código no console.

Ela evita execução acidental de scripts. A defesa vem de AMSI, Constrained Language Mode com controle de aplicações e log de ScriptBlock.

Questão 3 (ScriptBlock): A linha de comando mostra powershell -enc SQBFAFgA.... Onde ver o que o comando realmente fez?
Ver resposta explicada

Resposta: No evento 4104 (ScriptBlock) do log Microsoft-Windows-PowerShell/Operational.

O 4104 registra o script já decodificado. Também dá para decodificar à mão: o -enc é Base64 de texto UTF-16LE.

Questão 4 (Logon): Qual LogonType indica acesso por Área de Trabalho Remota, e qual indica acesso a um compartilhamento de rede?
Ver resposta explicada

Resposta: 10 para RDP e 3 para rede.

O tipo 2 é o logon no teclado, o 7 é o desbloqueio de tela e o 5 é o de serviço. O tipo muda o significado do mesmo evento 4624.

Questão 5 (Registro): Por que um malware que entrou por um usuário comum costuma usar a chave Run do HKCU, e não a do HKLM?
Ver resposta explicada

Resposta: Porque gravar no HKCU não exige privilégio de administrador, e a chave executa o programa a cada logon daquele usuário.

O HKLM vale para todos os usuários, mas exige administrador. Na investigação, revise as duas e compare com a lista conhecida.

Questão 6 (Serviço): O evento 7045 mostra um serviço novo com binário em C:\Users\Public, rodando como LocalSystem. O que isso representa?
Ver resposta explicada

Resposta: Persistência com o maior privilégio da máquina (T1543.003).

Serviços legítimos ficam em Program Files ou System32. Um binário numa pasta gravável por todos, rodando como LocalSystem, sobrevive a reinícios e dá controle total.

Fatos Essenciais, Referências e Próximos Passos

1. Objetos no pipeline

Verbo-Substantivo; Where-Object, Select-Object, Sort-Object e Group-Object; Get-Member mostra as propriedades.

2. Eventos-chave

4624/4625, 4672, 4688, 4720/4732, 4698, 7045 e 1102; LogonType 2, 3, 7 e 10.

3. Sysmon e 4104

Sysmon 1, 3, 11 e 13; o 4104 mostra o script decodificado.

4. Persistência

Run no HKLM e no HKCU, serviços e tarefas; execution policy não protege.
