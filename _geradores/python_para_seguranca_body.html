Introdução: Do grep ao Script Repetível

No Estudo 34, você investigou o web-loja01 com grep, awk, sort e uniq -c, e encontrou a força bruta de 198.51.100.23 terminando num login aceito da conta deploy. Funciona, mas cada analista monta a linha de comando de um jeito, e no próximo incidente tudo recomeça. Um script em Python faz a mesma triagem sempre do mesmo jeito, aceita formatos diferentes de log, consulta serviços de reputação e entrega o resultado em CSV ou JSON para o SIEM.

Expressões regulares com o módulo re

FunçãoO que faz
re.searchProcura a primeira correspondência em qualquer ponto da linha
re.matchSó aceita correspondência que começa no início da linha
re.finditerPercorre todas as correspondências, uma a uma, com os grupos de cada
re.compileCompila o padrão uma vez, para usar em milhares de linhas
  • Grupos nomeados (?P<ip>...) deixam o código legível: m.group("ip") em vez de m.group(3).
  • Um quantificador diz quantas vezes repetir: \d{1,3} (de 1 a 3 dígitos), \S+ (um ou mais caracteres que não são espaço), ? (opcional).
  • Uma âncora fixa a posição: ^ no início, $ no fim, \b na fronteira de palavra.
  • O grupo opcional (?:invalid user )? resolve o problema do Estudo 34: com ele, a mesma regex pega o IP com e sem "invalid user", sem depender da posição da coluna.
python — falhas de SSH por IP 
import re
from collections import Counter

FALHA = re.compile(
    r"Failed password for (?:invalid user )?(?P<usuario>\S+) "
    r"from (?P<ip>\d{1,3}(?:\.\d{1,3}){3}) port (?P<porta>\d+)"
)

falhas = Counter()
with open("/var/log/auth.log", encoding="utf-8", errors="replace") as arquivo:
    for linha in arquivo:
        m = FALHA.search(linha)
        if m:
            falhas[m.group("ip")] += 1

for ip, total in falhas.most_common(10):
    print(ip, total)

APIs de Reputação, JSON, CSV e Boas Práticas

Consultando reputação com requests

Serviços como o AbuseIPDB (pontuação de abuso de um IP) e o VirusTotal (análises de arquivos, domínios e IPs) têm APIs HTTP que respondem em JSON. A biblioteca requests faz a chamada; o script precisa:

  • passar sempre um timeout, para não travar esperando um servidor que não responde;
  • chamar raise_for_status para transformar respostas de erro (4xx, 5xx) em exceção tratável;
  • respeitar o limite de consultas: uma resposta 429 vem com o cabeçalho Retry-After dizendo quanto esperar (Estudo 13);
  • ler a chave de uma variável de ambiente ou de um cofre, nunca escrita no código que vai para o Git.
python — reputação de um IP no AbuseIPDB 
import os
import requests

CHAVE = os.environ["ABUSEIPDB_KEY"]   # defina fora do código: export ABUSEIPDB_KEY=...

resposta = requests.get(
    "https://api.abuseipdb.com/api/v2/check",
    headers={"Key": CHAVE, "Accept": "application/json"},
    params={"ipAddress": "198.51.100.23", "maxAgeInDays": 90},
    timeout=10,
)
if resposta.status_code == 429:
    print("Limite atingido; espere", resposta.headers.get("Retry-After"), "s")
else:
    resposta.raise_for_status()
    print(resposta.json()["data"]["abuseConfidenceScore"])

# VirusTotal: GET https://www.virustotal.com/api/v3/ip_addresses/{ip}
# com o cabeçalho x-apikey; o resumo fica em data.attributes.last_analysis_stats

Saída para pessoas e para máquinas

Um alerta em texto serve para o analista; para o SIEM ou uma planilha, gere CSV com o módulo csv (ele cuida das aspas e vírgulas dentro dos valores) ou JSON com json.dumps. Montar CSV concatenando strings quebra no primeiro valor com vírgula.

🔐 O que sai do script também é dado

Enviar um IP público a um serviço de reputação costuma ser aceitável; enviar nomes de clientes, e-mails ou arquivos internos não é. Antes de automatizar consultas a terceiros, confira o que a política da empresa e a LGPD permitem (Estudo 29), e trate erros para que uma falha no meio não deixe o resultado pela metade sem aviso.

Python do outro lado (T1059.006)

Atacantes também usam Python: scripts de varredura, clientes de webshell (o python-requests no access.log do web-loja01 é um exemplo) e cargas executadas em servidores com o interpretador instalado. Para a defesa, isso significa registrar a execução de interpretadores em servidores que não deveriam usá-los e desconfiar de agentes de usuário de bibliotecas em rotas sensíveis.

Checklist de um Script de Segurança

Use esta lista antes de entregar um script para a equipe usar. O estado das caixas fica salvo no seu navegador.

Questões de Fixação e Entrevista

Questão 1 (search ou match): Por que re.match(r"Failed password", linha) não encontra nada no auth.log?
Ver resposta explicada

Resposta: Porque re.match só aceita correspondência no início da linha, e as linhas do auth.log começam pela data e pelo nome do servidor. Use re.search.

Questão 2 (Regex): Como a mesma regex pega o IP em "Failed password for root from ..." e em "Failed password for invalid user admin from ..."?
Ver resposta explicada

Resposta: Com um grupo opcional sem captura, (?:invalid user )?, antes do usuário. Assim o IP é localizado pelo texto ao redor ("from ... port"), e não pela posição da coluna, que muda entre as duas formas.

Questão 3 (Counter): O que Counter.most_common(5) devolve?
Ver resposta explicada

Resposta: Uma lista com os 5 pares (valor, contagem) mais frequentes, do maior para o menor. Valores empatados mantêm a ordem em que apareceram.

Questão 4 (Segredos): Onde guardar a chave da API do AbuseIPDB usada pelo script da equipe?
Ver resposta explicada

Resposta: Fora do código: numa variável de ambiente ou num cofre de segredos, lida com os.environ. Uma chave escrita no script vaza no primeiro commit.

Questão 5 (requests): O script de reputação travou por horas numa madrugada. Qual parâmetro faltou?
Ver resposta explicada

Resposta: O timeout. Sem ele, requests pode esperar indefinidamente por um servidor que não responde.

Questão 6 (CSV): Por que não montar o CSV com print(valor + "," + str(total))?
Ver resposta explicada

Resposta: Porque um valor com vírgula ou aspas quebra as colunas. O módulo csv coloca os valores entre aspas e duplica as aspas internas quando necessário.
